## 1. What we already have (first-hand: the codebase map)
- **The game already speaks in events.** `src/engine/rules.ts:33` says they are "for animations, sound and online replays". The types are `placed · moved · cast · scored · drew · refreshed · tangled · turnStarted · gameOver`. The framework's `table/events.ts` has a `Listeners` hub made for "animations, sound, stats" that no game uses yet.
  - But a sound must land **on the animation's moment** (the seed landing, each score pop), not when the event arrives (that's earlier). So sounds attach to the animation code's moments.
  - `scoreSequence()` (`src/store/wordMarks.ts:87`) already gives the exact time of every pop and arrival, a ready-made sound schedule.
- **Feel tiers exist** (`content/tuning/feel.json` small / medium / big, used by turnPulse, noShake, seedPop, totalPop, refreshGrow). The game-feel rule says each tier gets a sound **in the same frame** as its visual. Same intention → same motion → same sound.
- **Settings already has an Audio tab** (`content/ui/settings.json`: master 80 · music 70 · sfx 80 · mute all · mute in background). Nothing reads it yet.
- **The Dev Kit's Screens sandbox already silences audio**, and its catalog (DEVKIT.md) plans an "Audio tool: click an event → assign a sound, volume, pitch variance, delay, preview". The save endpoint only writes `.json` under `content/` today, so **dropping in a sound file needs new Dev Kit work.**
- **Framework:** modules are copied into games (ui-kit, devkit, rooms, table, ai). "Audio module" sits in its roadmap's Later list: "comes out of Glyphtender's audio sprint".
- **Budget:** TDD §5 says first download < 2 MB including the dictionary, so audio must be small or load after the game starts.

## 2. Lessons from Muzzy's other games
- **Roll Better (sprint 13):** sounds generated by code (oscillators + noise) → Muzzy: **"horrible"**. Stripped to empty stubs; "real audio to come".
  → **Placeholders must be real recorded sounds** (CC0 packs), not code-made bleeps. Code-made sounds (ZzFX) are a tool at most, never the default.
  → Keep its good part: named hooks (`playScoreTick`…), so swapping a sound needs no code.
- **Windchime:** file-based Web Audio worked. Unlock on a tap, load after unlock, fades 50 / 150 ms, max 3 at once. iOS was never tested on a real phone.
- **Goops:** a master → music / sfx bus class. It works, but it's a one-off; that's what the module replaces.
- The `audio-setup` skill still recommends Howler + ZzFX placeholders. Update it to point at the framework module once built.

## 3. What indie games do (the standards, in plain English)
| Topic | The standard | Number to start from |
|---|---|---|
| **How loud overall** | measured in LUFS (average loudness); phone games run louder than console games | −16 to −18 LUFS · nothing above −1 dB · a limiter on the master as a safety net |
| **Volume groups (buses)** | master → music · ambience · effects · UI | UI 6–10 dB quieter than effects (heard hundreds of times) |
| **Ducking** | big moments push the music down briefly | −6 to −8 dB, 10 ms down, 600 ms back |
| **Not getting annoying** | 2–3 versions per sound, never the same one twice, tiny random pitch + volume | pitch ±0.5–1 semitone · volume ±1–3 dB |
| **Not stacking up** | per-sound limit + cooldown | 3–4 copies at once · 30–60 ms between repeats · ~12–16 sounds total |
| **Chained pops** | each pop a step higher on a musical scale (Peggle) | pentatonic (no wrong notes) · climb 8–12 steps · reset after 1–1.5 s |
| **Cozy tone** | soft attack, round tone (wood, felt, glass, water, plucked strings, marimba); one material palette; short | most sounds under 300 ms · avoid harsh highs |
| **UI sounds** | confirm goes up, cancel goes down, errors are a soft "bonk" (never a buzzer), hover silent | taps 30–80 ms |
| **Music** | quiet, layered, and it rests: after a few loops, fade to ambience only | 2–4 min loops · 3–5 short stingers for big moments |
| **Settings** | separate sliders + mute + mono; every important sound also shows on screen | Master 80 · Music 50–60 · Ambience 60 · Effects 80 · UI 70 |
| **Credits** | every file's source + licence recorded from day one | `content/credits.json` (already the BMUZ rule) |

**Middleware ideas worth borrowing (FMOD / Wwise, without the software):**
- Code plays **named events** (`seed.land`), never files.
- One data file maps each event to its files, volume, pitch, bus and limits.
- Random / sequence containers (variants).
- 2–4 **mix snapshots** (paused, reveal).
- Two **parameters**: combo step and music intensity.
- Skip 3D sound, blend containers and voice-over.

## 4. The tech (recommendation, for /define to confirm)
- **Our own thin layer on the browser's built-in Web Audio**, not Howler.
  - Howler's last release was 2023; it has no buses or filters, and its old-browser fallback no longer matters.
  - Tone.js is ~75 KB and built for music.
  - Web Audio already has everything: buses, filters, reverb, pan, fades, exact loop points.
- **Pitch and speed are one knob** for short sounds: faster = higher. Changing speed while keeping pitch is only cheap for music, so leave it out.
- **Phones:**
  - Sound starts on the first tap.
  - The **iPhone silent switch mutes web audio by default**, and it mixes with the player's own podcast or music. Overriding it stops their music. → Respect the switch by default; offer a Settings toggle.
  - After a call or tab switch, iOS may need another tap to come back.
  - Never queue sounds while audio is paused, or 20 play at once when it resumes.
- **Formats:**
  - Ship MP3 or AAC (works everywhere); Opus on iPhone is still flaky.
  - Short sounds are decoded into memory; music streams (a decoded 3-min track is ~69 MB).
  - Loop points live in the JSON, so loops are gapless.
- **Online:** your own action sounds on your tap, not on the server echo. Catch-up after a reconnect plays nothing (or one summary chime). Drop sounds older than ~0.5 s.
- **Testing:** the deciding part (which variant, limits, cooldown, pitch ladder) is plain code with normal tests. Playwright checks a log of what played (`window.__audioLog`), not the speakers.

## 5. What "tweakable in the Dev Kit" can mean (the menu)
**Per sound:**
- file(s) + variants (random / no-repeat / in order)
- volume (dB slider) · pitch (semitones) · random pitch · random volume
- delay · trim start/end · fade in/out · loop + loop points
- max copies · cooldown · priority
- bus · pan · low-pass / high-pass (muffle / thin) · reverb amount
- feel tier (small / medium / big) · which game moment triggers it

**Sound Board tab** (the tools in this list):
- every game moment, with ▶ and "▶ ×5" (hear the variation)
- drop a file onto a row to replace it
- waveform with drag handles for trim and loop
- A/B against the saved version
- "▶ in context": plays the real animation with the sound
- mixer with bus faders + level meters
- a "what just played and why it didn't" log while you play

**Script:** a loudness check / normalize (ffmpeg) so dropped-in files land at the same loudness.

## 6. Directions (diverge — pick in /define)
**A. Quiet garden** (Townscaper / Unpacking)
- Night ambience (crickets, breeze, a distant owl), soft foley for every action, no music.
- Cheapest, very cozy, and leaves room for the player's own music.
- Risk: the reveal has less "event" feel.

**B. The garden sings** (Wingspan / Mini Metro / Peggle) — *Claude's pick*
- Night ambience plus a very quiet musical bed in one key, and the **actions are the melody**: score pops climb a pentatonic scale, a long word rings a chord, a two-birds cast gets a flourish.
- The **Magic reveal is the crescendo**: each player's total counts up as a rising run, the winner gets a stinger.
- MDA: cozy cleverness gets an audible payoff for clever casts; Secret-Magic tension gets a musical build to "the gasp".
- Cost: everything must be in one key. Needs a music pass.

**C. Cozy soundtrack** (Wordscapes / Stardew / Dorfromantik)
- 2–3 background tracks + standard SFX.
- Familiar and easy to source (music packs).
- Risk: music fatigue over a 15-min game; the music doesn't react to play.

**Module scope:** layers can stop at any point; each is useful alone.
1. Core: events → sounds, buses, variation, limits, phone unlock, Settings sliders, credits.
2. Dev Kit Sound Board: tweak, swap, A/B, in-context, log.
3. Music: layers, stingers, snapshots, ducking, rest-after-N-loops.
4. Loudness script + the BMUZ skill update (audio-setup → the module).
